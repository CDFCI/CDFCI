# 三项独立候选：单节点跨 NUMA 验证结果

日期：2026-11-17。已批准的三个 Slurm 作业均完成，各版本均运行 2000 次。生产 CDFCI-mpi 和 origin 未作本轮修改，候选仍独立保存，未合并发布。

## 结论与证据强度

1. **接收缓冲复用：正确性通过，目标局部收益明确；总体收益尚需复核。** 两个 rank 的路由本地准备时间分别从 0.356939/0.361121 s 降至 0.196508/0.198825 s，减少约 45%。完整案例 Wall time 从 29.75 s 降到 29.17 s（本次减少 1.95%）。但是该改动直接减少的局部时间只有约 0.16 s，不能把完整的 0.58 s 差值全部算作优化收益；OpenMP 本地阶段也有波动。本例支持删除重复清零的方向，不足以承诺稳定的 1.95% 总体加速。
2. **并行发送复制：正确性通过，N₂ 性能验证没有覆盖并行分支。** 字节回归实际覆盖大消息与多线程路径；真实 N₂ 求解单次发送量在诊断版中最大为 rank0 617380 B、rank1 620340 B，均低于 1 MiB 启用门槛。相同输入、工作量和分工下，本轮求解使用小消息串行复制。Wall time 的 29.15→28.97 s 差值不能算作并行复制收益，路由本地时间也基本没变。
3. **前驱诊断：已定位大头，尚未实现新的算法优化。** pending 的临时哈希累计及首次波函数查询约 8.63～9.00 s，写回 worker 约 6.34～6.62 s；分片计数、scatter 等明显更小。两个 worker 的逐迭代不均衡损失在累计/写回中各只有约 0.04～0.06 s，当前 N₂ 小布局下，单靠重新均分任务可挖的空间很小。应优先研究哈希访问、分配和局部性是否可降低每条记录成本，而不是先改调度或加 Barrier。该诊断尚未分离哈希插入、首次波函数查询、内存分配各自耗时，不能宣布其中某一项已经是根因。

这些是一次基线→候选配对的观测，不是多轮重复的统计结果。三个作业同时占用同一共享节点的不同物理核，且基线始终先运行；共享内存带宽/缓存、运行顺序和其他作业的影响没有完全控制。

## 正确性与数据完整性

- 两项字节回归均退出 0。recv_reuse 覆盖串行/线程化两条交换路径、每条 10 个连续大小，含增长、缩小、等长、零消息，并与清空方案及期望字节逐一比较。
- parallel_pack 回归为 PACK_BYTES_PASS：35 组、2 rank，覆盖 worker=1/2/4/16/32、零/小/大/偏斜消息；rank0 检查 31470053 字节。该回归用于字节与顺序正确性，不用作性能结果；其中 worker 数大于求解分配核数的情况也仅用于正确性。
- 六次求解、每次两个 rank，共 240 份报告记录及 12 份最终记录。20 个报告点的 iteration/energy/dx/x/z/K 在 JSON 可见双精度数值上全部严格一致；每个 rank 在 20 个报告点的六项工作量计数也一致。
- 全部最终能量 -109.2740843323247901 Ha，x=31247、z=37642359、K=54993、dx=0.008605462684203844。无提前收敛、容量不足或异常中断。本轮没有导出并逐项比较完整波函数，正确性结论限定在已核对的数值轨迹、工作量和交换字节。
- 每个 rank 20 个 IO 事件均成功，单次导出事件与完整求解分开保存。138 个原始结果文件已生成 SHA-256 清单。

## 并行复制分支覆盖范围

源码采用 total_send >= 1024*1024 且 threads > 1 才并行最终复制，并保持 rank-major/thread-minor 顺序及不重叠目标区间。诊断版逐迭代 enum_worker 记录显示发送记录最大为 rank0 30869、rank1 31017；每条 20 B，因此最大为 617380/620340 B。逐报告点工作量和数值轨迹与 parallel_pack 案例一致，源码枚举分工相同，支持本次 N₂ 求解没有触发 1 MiB 分支的判断，但 parallel_pack 本身没有独立逐迭代分支计数器。

大消息并行路径已由字节回归覆盖，仍缺性能验证。不能为得到速度数字而把门槛改小并混称为同一个候选；需要后续获准的大消息受控测试或更大体系来评价该路径的性能。

## NUMA 近似的合理性与下一步边界

本轮合理地验证了两个 rank 的真实 MPI 交换、跨 NUMA 内存与本地计算、OpenMP 团队及数值不变；它足够检验接收复用的字节安全，以及大消息复制的顺序安全。它对短 N₂ 数据、每 rank 2 线程得到的相对收益只能代表此布局。

两 rank 始终在同一机器上，共享内存 MPI 不经过 paracloud 的跨节点 IB/RDMA 路径。两种缓冲候选主要针对本地内存操作，NUMA 验证有实际价值；但不能直接给 C₆H₆ 的 8～64 节点收益定量外推，也不能确认网络拥塞或 RDMA 通信变快。

建议接收复用保留为优先候选；并行复制保留为正确性已过、性能未验证候选；前驱工作继续聚焦累计/查询和写回的每条成本。当前不合并任何候选、不追加作业，等用户决定下一轮范围。
